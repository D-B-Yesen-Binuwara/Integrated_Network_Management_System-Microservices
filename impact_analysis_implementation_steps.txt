Impact Analysis Service - Implementation Summary

1. Initial Setup
- Created a new ASP.NET Core Web API project named `impact-analysis-service` inside the `Backend/services` directory.
- Manually created the `impact-analysis-service.csproj` file to include required dependencies (`Microsoft.EntityFrameworkCore`, `Npgsql.EntityFrameworkCore.PostgreSQL`, `Microsoft.EntityFrameworkCore.Design`, and `DotNetEnv`) after initial SSL connection errors with NuGet prevented automatic scaffolding.

2. Entities and DbContext Setup
- Created the `RootCause` entity to store detected root node failures.
- Created the `ImpactedDevice` entity to store the downstream devices impacted by root failures.
- Set up a one-to-many relationship using `ImpactAnalysisDbContext` with EF Core.

3. Repository Layer implementation
- Created `IRootCauseRepository` and `RootCauseRepository` for managing root cause operations.
- Created `IImpactedDeviceRepository` and `ImpactedDeviceRepository` to efficiently fetch, insert, and delete downstream relationships.

4. Client Integration
- Created `ITopologyClient` and `TopologyClient` using `HttpClient` to communicate with the Topology Service and fetch parent devices, child devices, specific device statuses, and all topology links. 

5. Service Logic (Core Analysis)
- Created `IImpactAnalysisService` and `ImpactAnalysisService`.
- Implemented `AnalyzeFailureAsync` to use a BFS traversal over the network topology to figure out if a failed node is an actual root cause or just a downstream casualty.
- Integrated cycle prevention (using HashSets) so the traversal will not loop infinitely on multi-path or cyclic network topologies.

6. Service Logic (Recovery and Promotion)
- Implemented `ClearRootCauseAsync` to delete root cause data and its associated impact subtrees when a device recovers.
- Implemented `ReevaluateDownstreamFailuresAsync` to handle situations where a recovered node was hiding other failed nodes. This dynamically checks the status of downstream nodes using `TopologyClient` and promotes them into new Root Causes if they are still DOWN without upstream issues.
- Implemented `RebuildImpactAsync` to recalculate from scratch.

7. API Endpoints
- Set up the `ImpactAnalysisController` exposing the required REST endpoints:
  - `POST /api/impact-analysis/analyze`
  - `GET /api/impact-analysis/root-causes`
  - `GET /api/impact-analysis/root-causes/{rootCauseId}/impacted-devices`
  - `POST /api/impact-analysis/clear/{deviceId}`
  - `POST /api/impact-analysis/rebuild/{deviceId}`

8. Application Configuration
- Created a `.env` file for setting `DefaultConnection` and `TopologyServiceUrl`.
- Updated `Program.cs` to apply Dependency Injection for all services, repositories, and clients.
- Ensured `context.Database.Migrate()` triggers automatically on application startup to ensure the `INMS_ImpactAnalysis` database is fully scaffolded in PostgreSQL.
